# Feature claim verification

This file defines the public claim boundary for the Jahiz Analytics showcase. It is intentionally conservative: a capability is described as shipped only when it is supported by current product guidance and public product evidence.

## Current product

| Capability | Public status | Safe public wording |
| --- | --- | --- |
| Athlete/player profile management | Current | Available |
| Live individual karate match logging | Current | Available |
| Scoring, penalties, timer and match review | Current | Available |
| Match analytics | Current | Available where exposed by the current app |
| Individual tournament workflows | Current | Available |
| Coach teams and team workflows | Current with role boundary | Coach capability where supported |
| Team tournaments | Current with role boundary | Coach capability where supported |
| Arabic and English mobile experience | Current | Available |
| iOS application | Current | Available on the App Store |
| Android application | Current | Available on Google Play |
| Public product launch | Current | Launch post: https://lnkd.in/p/eqWueRtk |

## Not represented as shipped

The showcase does not present the following as current shipped functionality unless product guidance is explicitly updated:

- billing/payment enforcement;
- plan/quota enforcement;
- report/export entitlement;
- AI-generated insights;
- video upload or video analysis;
- coach-athlete relationship/invitation workflows;
- organization or academy accounts;
- federation/organizer modes;
- public marketplace;
- advanced sharing/permission models.

## Quantitative claim policy

Volatile numbers such as commit totals, test-file counts, migration counts, screen counts, latency measurements, throughput claims and coverage percentages are not used as recruiter-facing proof unless they can be generated from a public source at review time.

The preferred format is **claim → engineering mechanism → evidence**, not adjective-heavy or time-sensitive metrics.
